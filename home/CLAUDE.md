# 작업 공통 규칙

## 1. 한국어 오타를 검토.
답변 혹은 노션에 본문을 작성 후, 보내기 전에 조사(을/를, 이/가), 받침, 띄어쓰기,
전문 용어 표기의 일관성을 검토

## 2. 명령을 안내할 때 실행 환경 먼저 고지.
모든 명령 블록에 환경 라벨을 붙임.
예: "(isaaclab_course) conda 환경", "환경 불필요 — 우분투 시스템 셸", "윈도우 PowerShell".

## 3. 작성하는 스크립트의 출력은 영어로, 주석은 한글 작성.
`print`와 에러 메시지 등 출력 문자열은 영어.
주석과 docstring은 한글.

## 4. 대대적인 변경은 보고한 뒤, 승인을 받고 실행.
대대적인 변경은 실측과 검증 후, 검증결과를 보고하고 승인 후 실행.
이때 다음 순서를 따름.
1. 보고: ① 만들려는 것(파일, 명령) ② 진행하면 일어나는 일(시스템 변화)
   ③ 진행하면 얻는 것(학습 포인트, 산출물)
2. 선택: 사용자가 매번 고름 "직접 실행"(명령과 파일 내용을 복붙 가능한
   가이드로 제공) 또는 "자동 실행"(Claude가 실행 후 보고).
3. 검증하고 기록한 뒤 다음 단계 보고로 넘어감.

## 5. 모든 삭제 여부는 사용자가 판단.
정리 작업을 요청받으면 각 항목의 정체, 크기, 최종 수정일, 다른 코드에서의
참조 여부, 중복 여부를 조사해 표로 보고하는 데까지만 함.
선택지를 나열하되 "권장" 딱지를 붙여 한쪽으로 몰지 않음.
삭제는 사용자가 명시적으로 지시할 때만 실행.

## 6. 메모리 갱신이 있으면 내용을 요약 보고.
`~/.claude/projects/*/memory/` 아래 파일에 무엇을 기록하거나 정정했는지 "요약만" 보고.
경로, 파일명, 수정 전후 원문은 적지 않음.
단, 사용자가 직접 물으면 그때는 보여줌.

## 7. 줄바꿈은 `.gitattributes`로 관리.
기본값은 `* text=auto eol=lf`.
윈도우 전용 파일(`.bat`, `.cmd` 등)을 추가할 때는 `*.bat text eol=crlf` 예외를 검토함.
